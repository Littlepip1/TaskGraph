# TaskGraph-MSC 一次运行实验包 v1

## 你需要执行什么

本包有一个总入口，会自动完成：组件核对 -> 开发参数比较 -> 参数冻结 -> 独立评价 -> 统计与回传打包。
不用分批手动运行，不会绘图，不需要AirSim，不需要原源码目录。使用现有Anaconda环境即可。
建议Python 3.10或更新版本；沿用原有Python 3.11环境最方便。

在Anaconda Prompt进入解压后的文件夹，第一次只需检查依赖：

```bat
cd /d "D:\你的路径\TaskGraph_MSC_AllExperiments_v1"
python -m pip install -r requirements.txt
```

正式一次运行全部默认实验：

```bat
python -u run_all_experiments.py --workers 4 --resume
```

也可运行 `RUN_ALL.bat --workers 4`。Linux/macOS可运行 `bash run_all.sh --workers 4`。
如果原环境已有numpy和scipy，不必重新安装。脚本不会主动升级环境。

运行中断后，再次执行完全相同的命令即可续跑。已完成且源代码/配置一致的回合会跳过。
电脑资源有限可设 `--workers 2`，资源充足可增加；选择耗时受并发影响。
控制台每完成一个回合显示进度和粗略剩余时间，不能保证不同机器具有相同运行时长。

默认252个开发回合、1536个独立评价回合，每回合240步。公共回合自动复用，不重复运行。
合计1788回合，是正式研究批次，不是短演示。需要保持终端和电脑运行。
开发与评价种子分离；每个评价条件12个环境种子。方法间使用相同外生随机数，感知几何由各自闭环决定。

只想先确认环境可用，可以运行下面的短流程。其结果另存，不污染正式批次：

```bat
python -u run_all_experiments.py --smoke --workers 2
```

查看工作量，不执行实验：

```bat
python run_all_experiments.py --plan
```

可选增加N=512：`python -u run_all_experiments.py --extended --workers 4 --output runs/EXTENDED`。
这会创建不同批次；需要在首次正式运行时决定是否使用extended，不能直接改旧批次的方案。

## 包含的实验

| 模块 | 设计 | 目的 |
|---|---|---|
| 单任务比较 | N=64，SP/MIS，4096/256 bit每链路每步 | 与单任务研究主线衔接，比较自适应方法 |
| 局部任务扩展 | N=64/128/256，任务数2/4/8，平均32人一项任务 | 检查总服务、人均服务、候选访问和计算耗时 |
| 多任务交接与消融 | N=128，4项任务，有重叠协调成员及实际角色交接 | 检查分组、准备窗口、共享成本、保护项与搜索 |
| 群组增长压力 | N=64/128/256，始终2项任务 | 区分团队增长与单项任务变大的影响 |
| 接收上下文敏感性 | 接收者信息滞后0/8/16步 | 检查选择器对陈旧信息的敏感性 |
| 理论逐回合核对 | 需求遗漏、可行参考集合上界、实际服务记账 | 核对实现与理论条件 |

两个任务类型覆盖所有默认模块。角色交接发生在回合中点。
协调成员真正以两个目标估计的加权参考位置执行控制；交接成员从一个目标切换到另一个目标。
所有任务共享一个物理网络并发传输，而不是把多个独立64人结果拼起来。
任务计划对所有方法相同，组间成员可以充当中继。各方法的物理转发均支持共享载荷。

## 方法标签

| 标签 | 含义 |
|---|---|
| dense_task | 准备群组内密集通信；主要控制参考；不使用源端信息价值抑制，但检查物理可用性 |
| dense_global | 向全体可达成员传播；用于观察无任务过滤的负担 |
| full | 控制动作平方评分、估计保护、任务准备、共享路径、双向搜索与可行参考集合 |
| demand_only | 相同控制评分，仅按需求大小构造达到要求的集合 |
| legacy_additive | 使用原动态选择中动作与协方差改善的加性思路，重新在开发集校准 |
| uncertainty | 根据接收者预计协方差下降自适应选集合 |
| innovation | 根据接收者归一化新息自适应选集合 |
| no_group | 全体可达成员进入需求考察，无关任务需求记零 |
| no_prepare | 只使用当前依赖；取消提前/交接准备保护窗口 |
| no_shared | 选择时按独立路径费用，实际网络仍共享载荷 |
| forward_only | 保留前向和可行参考集合，不执行反向删减 |
| no_guard | 不使用不确定性保护项 |

所有选择均无固定接收人数上限。完整方法与规则比较方法分别在开发集选遗漏比例；消融继承完整方法参数。
开发候选为theta=0/0.1/0.25/0.4，要求四个环境的配对95%回报差区间上端均不超过0.008，再选平均服务节省最高者。
正式评价容差为0.01。无合格开发配置时保留theta=0回退并标为未校准通过，不会声称成功。
绝对遗漏量设为0，避免随团队平均归一化造成额外规模依赖；该设置是新协议，不与旧1e-6设置混同。
完整独立评价结果不用于重新选参数。`development_frontier.csv`只用于开发集权衡分析。

## 结果在哪里

完成后自动生成 `runs/ALL_EXPERIMENTS_RETURN.zip`，整个回传包发给助手即可。

重要文件：

- `ACCEPTANCE_CN.md`：统一验收结果，分开报告执行成功与性能判据通过。
- `paired_summary.csv`：种子配对回报差、最差任务差异、服务节省、候选量、耗时及95%区间。
- `scaling_summary.csv`：局部任务扩展时相邻规模的人均服务比和总服务比。
- `theory_audit.csv`：需求可行性与通信计数核对。
- `episodes.csv`：每回合汇总；每个evaluation/*.json还有逐步trace，供以后画图。
- `FROZEN_SELECTION.json`：正式评价前确定的参数；不要手工改动。
- `manifest.json`：配置与代码摘要；`evaluation_plan.json`给出所有回合与模块对应关系。
- `tests.log`：预检；失败回合写入对应`.error.json`，重新运行会只补跑缺失/失败部分。

前一次运行失败也会尽可能汇总已完成评价；只有所有预定回合齐全，execution_complete才为true。
需要重新汇总而不再运行：`python run_all_experiments.py --summarize-only --resume`。

## 必须了解的证据范围

1. 本包沿用ServiceOpt-v3的估计器、感知模型、控制器、源端门控和逐跳队列网络，新增真实多任务闭环。
   网络几何构造作等价向量化加速，并有与原实现的路径一致性检查。
   新场景、新机会相位和新参数协议意味着新结果不能冒称旧批次逐数值复现。
2. 接收者信念由基准提供；其获取开销、路由发现信令未计入载荷成本。陈旧上下文测试不是分布式副本维护。
3. 规则比较方法不是CommFormer/T2MAC/HYGMA/ExpoComm的完整训练复现。本包没有捏造这些方法的实现。
   正式强基线需要原训练/推理代码和权重，可通过下面接口加入；验收报告会明确标记当前缺口。
4. 上界核对分开处理固定路径快照和实际动态服务。实际运行的observed_K是记账量，不是先验线性扩展证明。
5. 线性理论依赖有界任务规模、每源任务数与服务跳数。有限几个规模的曲线只检验相应有限范围。
6. 不自动保证最优、不保证一定胜出、不把冒烟结果作为性能证据，也不把单任务均值等同于所有任务都通过。
7. 统计独立单位是环境种子，不是时间步或消息。95%区间为逐条件区间，不是所有条件同时覆盖的区间。
8. 路由图构造仍考虑全体节点，其耗时单独记录。候选查询局部化不等于整个程序运行时间必然线性。

## 文件组织

`run_all_experiments.py`是唯一总入口；`tgexp`是新增实验逻辑；`vendor_service_v3`保留原底层源码及摘要。
采用一个入口加内部模块，便于检查与定位问题，使用时只需要运行一个命令。
本包不包含图形生成器，也不要求逐步人工干预。
