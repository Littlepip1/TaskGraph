# TaskGraph-MSC：动态少数成员需求实验

本次交付为 v1.1，沿用之前确定的实验设计和 v1 仿真实现。新增正式结束前的自动独立核验，以及只查看工作量的 `--plan-only`；需求评分、集合算法、传感器、估计器、控制器和网络实现不变。

本包实现“多数成员本地观测正常，少数成员暂时缺测，缺测对象随时间变化”的闭环实验。比较完整方法、随机接收、最近距离、固定轮询和固定周期发送。重点观察关键成员是否及时获得新信息，以及达到相同控制要求所需的实际服务成本。

## 一次运行全部正式实验

使用原来的 Anaconda 环境。将整个文件夹解压，在 Anaconda Prompt 中进入该文件夹，运行：

```bat
RUN_ALL.bat
```

等价命令：

```bash
python run_dynamic_demand.py --mode full --workers 6
```

Linux/macOS 使用 `bash RUN_ALL.sh`。已有 numpy、scipy 的环境可以直接运行；缺少依赖时先运行 `python -m pip install -r requirements.txt`。无需安装 AirSim；这是沿用原估计器、控制器和动态链路服务实现的运动学仿真。

建议使用 Python 3.10 或更高版本。可先查看正式任务数，不运行仿真也不创建结果：

```bash
python run_dynamic_demand.py --mode full --plan-only
```

正式结束后只需返回：

```text
runs/full/DYNAMIC_DEMAND_RETURN.zip
```

程序自动完成开发、参数冻结、独立评价、配对分析、比较报告、原始记录独立核验和打包。独立核验检查任务是否齐全、共同预热与名单是否一致、计费差分是否正确，并重新计算团队、最差任务、最差事件及成本的区间；核验成功后才记录最终完成并打包。中断后运行原命令即可续跑。需要降低负载时将 `--workers 6` 改为4或2；进程数不会改变实验条件或种子。代码和协议修改后应使用新的输出目录，不要将旧回合混入。

## 场景

- 128智能体、4个固定但重叠的任务，采用现有SP连续转弯轨迹。
- 384步，每步0.5秒。前64步所有方法共同采用任务内密集通信，位置、估计器和队列连续运行。
- 在第64、144、224、304步，每个主任务3个成员的本地观测中断32步。约12/128=9.375%的成员同时受阻。
- 正常：没有额外中断，保留原传感器自然漏检。
- 分散缺测spread：每步重新选择受阻成员，阻断时槽数与持续中断相同。
- 固定受阻fixed：四个窗口均为同一批成员。
- 轮换受阻rotating：每个窗口更换成员，连续窗口不重叠。
- 容量为每链路每步4096或256 bit；消息352 bit，截止时间32步。
- 四种观测条件×两种容量×16步发送机会间隔，得到8条件。
- 正常、轮换×两种容量×64步发送机会间隔，另有4条件，检验通信机会较少时的表现。

受阻名单由外生种子提前生成，所有方法共享相同名单。名单只用于本地观测生成和评价，不进入策略。发送相位在各主任务内部平衡分配，使用独立随机流，避免智能体编号和长发送周期产生整段无机会的偶然关系。

不同方法共享目标轨迹与外生随机数。闭环位置发生差异后，几何检测概率与观测噪声协方差也可相应变化，不强行锁定观测值或未来拓扑。

## 方法与参数

| 方法 | 参数 |
|---|---|
| 完整方法full | 允许遗漏比例0、0.05、0.10、0.20 |
| 随机random | 保留10%、25%、50%、75%接收者 |
| 就近nearest | 同上 |
| 轮询round_robin | 同上；每个源端—任务维护独立循环游标 |
| 周期periodic | 每2次或4次发送机会发送一次 |
| 密集dense_task_reference | 100%端点，各简单家族共用 |
| 无新发送no_new_communication | 预热后不生成新通信 |

共20个配置。简单方法只用当前任务标签、可达候选、随机数或距离，不使用接收者估计、控制评分、源端自适应触发和未来任务准备机制。轮询可防止固定遗漏同一批接收者。

轮询的初始位置按源端—任务分别使用独立随机流抽取，各回合可复现，使服务起点分散。

完整方法的需求评分、源端触发、集合求解和物理模块沿用原实现。新增内容是外生场景、共同预热、简单轮询规则和评价记录。`reference/engine_before_dynamic.py`保留修改前入口以供回归核对。原完整方法0.10配置在 `paired_vs_original_full_0p1.csv` 单独保留。

## 控制要求与独立评价

每个回合与同种子密集参考配对。联合通过标记要求以下三个指标各自的配对95%区间上限不超过0.01：

1. 团队平均回报损失。
2. 最差任务回报损失。
3. 四次受阻事件中最大的成员回报损失。

固定和轮换条件的事件窗口覆盖受阻32步及随后16步恢复。正常条件使用同一虚拟成员集合。spread的主事件指标为实际缺测成员—时刻，另保存一致口径的 `matched_cohort_reward` 供跨条件图使用。恢复窗口指标和即时成员指标有明确标签。

按条件、按方法家族，先在4个开发种子上选择满足控制要求且实际成本最低的配置，冻结后再运行12个独立评价种子。所有配置仍完整评价，结果不会筛掉不利比例或条件。完整方法在开发集无合格配置时标记未合格，不根据测试数据另选配置。

正式共12×20×(4+12)=3840回合。置信区间以种子为单位，逐条件逐指标计算；不是跨所有比较的同时95%保证。源端触发阈值和控制器不在本实验中重新调节。

## 实际成本与更新指标

主成本为第64步起实际提供的有效载荷bit-hop，包含部分传输、最终过期包，以及预热遗留包后续消耗的服务。因此“无新发送”的评价成本可能大于零。预热成本单列，队列不清空。

更新指标包括：受阻开始后首次收到新鲜远端观测的时间，4、8、16步内获得更新的比例，整个窗口没有更新的比例，以及协方差、估计误差和控制误差。无更新者保留，等待按窗口长度截断。normal和spread的持续成员更新指标为虚拟匹配群体诊断，标签与真正持续受阻群体分开。

首次更新指收到任一当前相关任务的新鲜观测，不等同于控制已经恢复；控制效果由独立的回报指标判断。

`nonblocked_selected_copies`只是分配给当前未受阻成员的接收服务，不能直接解释为浪费。程序每16个机会左右做一次固定哈希采样的离线价值诊断；其结果不进入策略，开销独立记录。源端拒绝、接收集合遗漏和网络到达延迟分别记录。

接收者状态获取和拓扑发现的信令仍未计费。本包检验现有信息条件下的有效载荷通信策略；状态维护成本需单独实验。

## 优先查看的结果

- `COMPARISON_CN.md`：自动生成的可读验收与比较。
- `heldout_selected_comparison.csv`：开发集冻结配置后的正式配对比较。
- `evaluation_curves.csv`：全部配置的通信成本与三个控制指标。
- `paired_vs_original_full_0p1.csv`：原0.10完整方法与各简单配置的比较。
- `mechanism_effect_no_new_communication.csv`：无新通信时，轮换受阻相对正常观测是否确实增加估计及控制损失。
- `stage_counts.csv`：有效观测机会、物理可行、源端触发和接收集合选择。
- `fresh_updates.csv`：逐受阻成员的首次新鲜更新和未更新记录。
- `time_series.csv`：误差、协方差、受阻成员更新率随时间变化，可直接画图。
- `value_audits.csv`：固定采样的离线代理价值诊断，包含源端未触发的机会。
- `development_episodes/`、`evaluation_episodes/`：完整原始回合、事件和时间序列。
- `protocol_freeze.json`、`selected_on_development.json`、`manifest.json`：协议、选择和环境。
- `independent_audit.json`：自动独立核验结果；最终 `acceptance.json` 的 `independent_audit_passed` 应为 true。

`calibrated_common_quality_advantage=true`要求开发选择有效、双方评价控制均通过，且完整方法额外节省的配对95%区间下限大于零。其余情况保留原始数值，按实际证据解释。

## 可选检查

```bash
python -m unittest discover -s tests -v
python run_dynamic_demand.py --mode smoke --workers 6
python run_dynamic_demand.py --mode pilot --workers 6
```

smoke为16智能体、96步、6条件，共480回合，只检查程序。pilot为64智能体、384步、两个轮换条件、每阶段2种子，共160回合；是完整时域预运行。正式运行直接用full即可。

若需要每个智能体每步的原始数组，加 `--agent-arrays`，程序将保存压缩NPZ；这会明显增加返回文件体积。默认原始JSON保留未四舍五入的事件及时间序列统计，用于重新计算主指标与配对区间。

正式运行后重新汇总可用 `--summary-only`；代码和输出目录应与原运行一致。单回合报错时程序保存错误并停止继续提交结果，完成的回合可在修复后按原代码协议续跑；代码有改变则使用新输出目录。

还可运行 `python tests/audit_completed_stage.py runs/full`，从原始回合独立核对任务清单、共同预热、计费差分及主指标的配对区间。该步骤不重新仿真。
