# TaskGraph-MSC：少数成员需求随时间变化的对比实验设计

版本：DynamicDemand-Design-v1。本文是实验协议，尚未实现或运行本组新实验，不包含性能结论。

## 研究问题

当大多数智能体仍能依靠本地观测维持控制，而少数成员暂时失去本地观测、且失去观测的成员不断变化时，完整方法能否以更少的实际通信服务维持相同控制质量？

不预先假定受阻成员一定急需通信。先通过无通信对照检查：观测中断是否使其估计和控制明显变差，以及及时接收远端观测是否改善这些量。

## 一、场景和时间线

主场景采用128智能体、4个固定但有重叠的任务，沿用当前SP连续转弯目标轨迹、传感器基础噪声与检测概率、控制器和动态网络。任务角色在一个回合内不切换，以分离“接收需求改变”与“任务成员改变”。本组不叠加旧MIS场景的额外缺测规则。

| 参数 | 预设值 |
|---|---|
| 智能体/任务数 | 128/4，每个主任务约32个成员 |
| 仿真步长 | 0.5秒 |
| 总时长 | 384步，包含前64步共同预热 |
| 共同预热 | 第0至63步，各方法均采用任务内密集通信 |
| 正式评价 | 第64至383步 |
| 观测中断开始时刻 | 第64、144、224、304步 |
| 每次中断持续时间 | 32步，即16秒 |
| 每个主任务受阻成员数 | round(0.10×32)=3个；128智能体共约12个 |
| 实际受阻比例 | 12/128=9.375%，按实际人数报告 |
| 消息截止时间 | 沿用32步 |
| 链路容量 | 每链路每步4096或256 bit |
| 消息有效载荷 | 沿用352 bit |

每个智能体按原有主任务划分归属；有重叠控制依赖的成员只在一个主任务内参加受阻抽样，避免重复抽取。受阻期间，该成员的所有本地目标观测均不可用，但运动、接收、转发和控制继续运行。本地观测恢复后仍使用原传感器模型，不强制提供完美观测。

预热结束时不清空队列、不重置估计器、不重置位置和发送历史。主通信成本为第64步起实际提供的有效载荷bit-hop，包括此后对预热遗留包的服务；预热成本单独报告。相同种子和条件下，各方法在预热结束时应具有相同状态与队列。

## 二、四种观测条件

| 条件 | 实现 | 回答的问题 |
|---|---|---|
| 正常观测 | 不添加额外中断，保留原传感器自然漏检 | 没有额外异质需求时是否仍有收益？ |
| 分散短时缺测 | 在每个中断窗口内，每步在各主任务随机选择3人缺测，下一步重新抽样 | 同样数量的受阻时槽，若不持续集中在少数人身上，会怎样？ |
| 固定少数成员受阻 | 每个主任务选定3人，四个窗口始终是同一批人受阻 | 固定关注某些成员是否已经足够？ |
| 少数成员轮换受阻 | 每个窗口更换3人，连续窗口的受阻集合不重叠 | 方法能否跟上需求在不同成员之间转移？ |

分散、固定、轮换条件每步阻断的成员数量相同。控制的是额外受阻时槽数量；由于自然漏检和闭环几何位置不同，实际被抑制的有效观测条数不保证完全相同，必须记录该数量。

受阻名单由环境种子与独立随机流在实验开始前生成，依据智能体主任务均匀抽样。不得依据完整方法的需求分数、基线选择结果、位置远近或实验回报生成名单。固定和轮换条件第一窗口使用相同名单，后续窗口才分开。所有通信方法共享同一名单和时间线。

名单不传递给任何通信策略，也不以额外权重、优先级或强制发送规则进入完整方法。完整方法仍通过已有估计状态与控制需求评分作出选择；各成员自然知道自身此刻是否得到本地观测。

## 三、通信机会的两个预设范围

不能假设随机删减后信息就不足。源端很多时，一个受阻接收者仍可能不断收到其他人的信息。因此预先设置两组机会密度，并同时保留结果。

1. 主组：发送机会间隔16步，四种观测条件×两种容量，共8个条件。
2. 较少发送机会组：间隔64步，只比较正常观测与轮换受阻×两种容量，共4个条件。

机会间隔64步可以对应较低通信占空比。它是所有方法共同面对的外部限制，不改变某个算法的评分或收发权限。

为避免智能体编号恰好令某个任务整段时间没有发送机会，在每个主任务内部为源端预分配尽量均匀的发送相位，再用独立随机排列对应到成员。相位在回合开始前固定；不同算法使用相同相位。16步和64步两组都采用相同的分配原则。只记录并按物理条件使用当前发送机会，不告知未来受阻名单。

每次仍只有当前有有效本地观测、获得发送机会且满足共同物理可行条件的源端可以发送。不得保证某条关键消息必然生成或必然能到达。

正式主体共12个条件。64/1、256/8团队规模，受阻比例5%和20%，持续时间16和64步，可作为后续预设敏感性实验，不与主体结论混合。

## 四、比较方法和参数

主比较均限于当前任务相关、可达的接收者，防止优势只来自省掉向无关任务发送的信息。当前任务标签对各方法相同；简单方法不构建未来任务超图，不读取接收者估计，不使用需求分数、自适应源端触发或切换保护。

| 方法 | 决策规则 | 预设参数 |
|---|---|---|
| 完整方法 | 保留现有需求评分、源端触发与集合构造 | 允许遗漏比例0、0.05、0.10、0.20 |
| 随机接收 | 每次均匀随机选择接收者 | 保留10%、25%、50%、75% |
| 最近距离 | 选择距源端最近的接收者 | 同上 |
| 固定轮询 | 按接收者ID循环分配服务，不判断需求 | 同上 |
| 固定周期 | 每2次或4次源端机会向当前任务成员发送一次 | 周期倍数2、4 |
| 任务内密集参考 | 每个物理可行机会向任务内可达成员发送 | 同时作为各简单家族100%或周期1的端点 |
| 无通信 | 仅依靠本地观测 | 不产生有效载荷通信 |

共20个不同配置：完整方法4个，随机4个，就近4个，轮询4个，周期2个，密集1个，无通信1个。100%端点不重复运行。

简单接收规则每次保留ceil(p×M)人，M为当时可达的任务内候选数。随机接收不同保留比例采用同一个随机排列的前缀；轮询维护每个源端—任务的循环游标，不能固定遗漏同一批接收者。

完整方法原来的0.10配置必须单独保留和报告。其他允许遗漏比例用于预设的成本—控制比较，不改变控制器、源端触发阈值、需求公式或集合算法。

所有方法使用同一物理路由、共享转发、服务容量、队列和消息截止时间。策略改变控制位置后，之后的拓扑可以随各自轨迹改变；不强行锁定未来位置或未来网络。

## 五、控制与通信评价

### 1. 全局与任务控制

沿用当前归一化控制回报，同时记录团队平均回报损失和最差任务回报损失。每个种子都与同种子、同观测条件的任务内密集参考配对。

### 2. 受阻成员的事件损失

设第e次中断从s_e开始，持续D步，受阻集合为B_e。评价窗口W_e为从s_e至s_e+D+16的左闭右开区间，覆盖观测中断和随后8秒恢复过程。对每个种子计算：

L_e = 在r属于B_e、t属于W_e的所有成员—时刻上，平均的[R_dense(r,t) − R_method(r,t)]。

R_dense和R_method是该成员该时刻的控制回报，使用仿真真值评价，不提供给算法。再记录四个事件的平均损失以及最大事件损失max_e L_e。分散缺测条件没有固定持续受阻人群，其事件指标取窗口内各时刻实际受阻的成员，并另报告即时成员—时刻损失；该指标不与固定人群的恢复指标直接混称。正常条件事件指标采用与轮换条件相同的预设成员集合，作为匹配参照。

共同控制判据预设为：团队平均损失、最差任务损失、最大受阻事件损失各自的配对95%置信上限均不超过0.01。最后一项用于防止少数成员的损失被团队平均值稀释。分散条件报告其对应的即时事件指标，恢复过程作为单独诊断。

置信区间以独立环境种子为单位。窗口、成员和消息不是独立样本。上述区间分别报告，不能称为跨所有指标、方法与条件的同时95%保证。

### 3. 更新是否来得及

在固定和轮换条件中，对每名受阻成员记录：

- 中断开始后首次收到“生成时间不早于本次中断开始”的有效远端观测所需时间。
- 开始后4、8、16步内至少收到一次上述更新的比例。
- 整个受阻窗口没有收到上述更新的比例。
- 收到的不同有效观测数、观测年龄及接收后的协方差与跟踪误差变化。

预热生成的旧消息不计入本次新鲜更新，但其真实控制作用仍由回报评价保留。没有收到更新的成员必须保留；报告失败比例，并以窗口长度截断计算平均等待时间，不能只统计成功收到的成员。

### 4. 实际通信量

主指标是正式评价区间实际提供的有效载荷bit-hop，包括部分传输、最终过期以及来自预热队列的服务。另报告请求发送量、及时到达率、过期量和期末未完成队列。不能只统计成功到达的包，也不能用“选择人数”代替实际成本。

归一化成本以评价区间的智能体数×步数为分母。总量与人均每步成本同时保留。

## 六、先验证需求确实集中，再解释性能

首先比较无通信条件下，轮换受阻和正常观测的同种子结果：受阻成员的协方差、估计误差和控制损失是否在窗口内上升，其他成员是否相对稳定。然后检查密集通信是否缓解这些变化。

如果中断只增加协方差而几乎不影响控制，说明该设置下运动预测已足够好，不能直接把受阻名单称为“急需通信成员”。该条件仍保留，作为需求较弱的结果。预设的不同机会密度与后续持续时间扫描用于观察需求何时变强，不在看到测试结果后挑选对完整方法有利的种子。

对完整方法另做固定采样的离线诊断：

1. 有效观测与发送机会是否存在；
2. 源端触发是否允许发送；
3. 受阻接收者是否进入所选集合；
4. 选中后是否按时获得服务；
5. 收到后控制是否改善。

尤其需要区分源端触发和接收集合构造：接收者需求升高，并不保证一个自身状态良好的源端会触发。诊断可以离线计算被拒机会的潜在接收价值，但不得将该诊断反馈给正式策略，且其开销与在线选择计时分开。

## 七、开发、冻结与评价

- 开发种子：2710900000至2710900003，共4个。
- 评价种子：2710901000至2710901011，共12个，与旧实验及开发集分开。
- 按条件、按方法家族，在开发集选择满足共同控制判据且实际成本最低的配置，随后冻结。
- 若某个简单家族没有非密集配置通过，选择其预设密集端点并如实标明。完整方法若无配置通过，标记未找到合格配置，不更改触发阈值或隐去该条件。
- 评价集保留全部20个配置，展示完整的离散成本—控制结果，同时单独报告开发集选定配置的配对比较。
- 同成本比较只对实际成本相近的点报告；不根据名义保留比例认定成本相同，不用未经验证的插值宣称控制达标。
- 场景、随机流、参数网格、判据和代码指纹先冻结。测试结果不用于回调本版参数。

主体工作量：12条件×20配置×(4开发+12评价种子)=3840回合。可用统一入口一次运行，逐回合保存并支持中断续跑。

## 八、计划输出及解释

1. 参数表与场景时间线，清楚标明受阻名单如何轮换。
2. 正常、分散、固定、轮换四类条件的通信—控制曲线，所有预设点均保留。
3. 受阻事件前后，受阻与未受阻成员的误差、协方差、远端更新率随时间变化。
4. 独立开发选择后的配对成本差、团队控制和受阻事件控制判据。
5. 各阶段诊断计数：源端机会、触发、接收集合、到达、控制响应。
6. 完整原始回合、种子清单、参数选择记录、代码指纹与计费核对。

如果完整方法在轮换受阻时，以更低成本通过相同控制判据，并更快更新受阻成员，就支持“按变化的接收需求分配通信”的价值。如果简单轮询同样好，则说明固定覆盖在该条件已足够；如果完整方法选中了成员却消息未及时到达，则进一步研究应集中在时延和排队；如果源端没有触发，则应研究源端触发与接收需求之间的联系。

本实验衡量整套方法相对直觉规则的效果。超图分组与成组删枝各自的额外贡献，仍由相应的共享框架消融解释。

成本口径沿用现有仿真：完整方法使用基准提供的接收者状态，状态获取与拓扑发现的信令尚未计入。受阻名单和未来时间线对算法隐藏。状态获取计费应作为独立实验，不能由本实验代替。
